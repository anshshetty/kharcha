# Design System: Kharcha

## Overview

**Creative North Star: "Understand this month"**

Kharcha uses Manrope, cool neutral surfaces, charcoal text, forest green selections, blue fixed spending, and ochre unavoidable spending. The compact shell supports a readable financial report with flat persistent sections and restrained overlay depth.

Graphics explain recorded ledger amounts and open their supporting payments. The custom receipt illustration marks connection and empty states without supplying numerical evidence. This record describes the final implementation; theme-prefixed frontmatter tokens are normative and correspond to :root and .dark in frontend/styles/tokens.css.

**Key Characteristics:**

- Compact controls, explicit states, and restrained corners.
- Semantic roles shared by light and dark themes.
- Tabular amounts and graphics grounded in accounting evidence.
- Visible category scope, save status, and recovery actions.

## Colors

Theme-prefixed names map directly to the source custom properties. CSS aliases are resolved into literal colors because frontmatter primitives cannot reference one another. Color strings retain their normative source notation.

### Primary

**Forest selection** uses primary, primary-hover, and primary-foreground for affirmative actions, selection, and focus. Regular spending has its own graphic-regular semantic role within this family.

### Secondary

**Fixed blue** uses graphic-fixed for fixed spending and negative monthly marks. The separate info family supplies information messages.

### Tertiary

**Unavoidable ochre** uses graphic-unavoidable. Warning, success, danger, and purple families retain their shipped message/insight roles; group colors do not imply a financial judgment.

### Neutral

Background, card, surface-raised, secondary, and accent define page and tonal layers. Foreground and muted-foreground define reading hierarchy. Sidebar has dedicated default, heading, active, hover, and muted roles. Preserve the corrected light-sidebar-foreground value from the source.

Border divides sections; input-border gives fields a stronger edge. Warm and hero roles serve existing supporting metric/context surfaces. Chart-1 through chart-6 supply category colors; chart-bar, chart-current, and chart-current-border distinguish ordinary and current-month marks. The categoryColor() hash in frontend/lib/design-system.ts preserves category identity across sorting and filters.

**The Semantic Color Rule.** Preserve the regular, fixed, and unavoidable group meanings across themes; category color follows its name rather than rank.

**The Evidence Before Decoration Rule.** Derive financial graphics from recorded ledger amounts and accompany color with labels and amounts.

## Typography

**Display Font:** Manrope, with Avenir Next and platform sans-serif fallbacks.
**Body Font:** The same Manrope stack.
**Label/Mono Font:** Manrope labels; ui-monospace for source evidence.

The bundled variable face spans weights 200–800, loads with font-display: swap from /fonts/manrope-variable.ttf, and uses a 16px root. Source: frontend/styles/foundation.css.

### Hierarchy

- **Display:** Monthly spending total; reduced to 3rem at 1150px and below.
- **Metric:** Fluid supporting financial metric.
- **Title:** Page heading; overridden to 1.6rem on mobile.
- **Headline:** Regular section heading. Compact report headings use body-compact size and weight 650.
- **Body / Body Compact:** Base reading and compact product text.
- **Label:** Quiet annotations; smaller monthly/mobile legend labels remain graphic-specific exceptions.
- **Control:** Compact action text. Sidebar weights are 550 by default and 700 when selected.
- **Evidence:** Monospaced, preformatted source text, with its observed size and line height.

Frontmatter owns the observed scale; no geometric ratio is asserted. Totals, table amounts, trends, and split allocations use tabular numerals. Headings use balanced wrapping. Connection copy has a local 40ch maximum, rather than a global prose-width rule.

## Elevation & Depth

Popovers and selectors use Tailwind shadow-md; sheets use shadow-lg. Dialogs use a foreground ring; modal backdrops use black at 10% opacity and a supported 4px blur.

### Shadow Vocabulary

- **Report surface:** none, from tokens.css.

- **Sheet:** imported shadow-lg, used in frontend/components/ui/sheet.tsx.

**The Flat Report Rule.** Separate persistent report surfaces with tone and borders; reserve overlay shadows for popovers, selectors, and sheets.

### Automatic Corrections & Category Memory

Show matching scope at the category edit: this payment only, future payee-name matches, confirmed person, or confirmed person plus exact amount. Confirmed-person options require identity confirmation and a key. Matching preserves currency and direction and leaves earlier payments unchanged. frontend/lib/payee.ts defaults recognized merchants to payee matching; other names require selected scope except confirmed-person defaults. Bank email senders remain evidence metadata.

frontend/lib/autosave.ts serializes detail requests and coalesces typing after 650ms. It retains the exact failed draft and operation identifier for explicit Retry. Detail sends changed fields with expected values, pauses incomplete drafts, and does not write on initial opening. Status exposes pending, saving, saved, error, or incomplete states, with Undo after success. Draft recovery uses session storage when available. Closing flushes edits and stays open on failure; Reload/Discard restores saved state, and before-unload guards dirty work. frontend/components/transaction-detail.tsx owns this flow. New manual payments retain their explicit create action.

Quick category changes save immediately, disable controls during an unresolved attempt, retain drafts on error, and retry with the same identifier. Undo restores the prior category and associated rule change. Source: frontend/components/category-quick-edit.tsx. A readable save indicator accompanies the spinner.

## Do's and Don'ts

### Do:

- **Do** use semantic custom properties so controls, text, and graphics follow the active theme.
- **Do** pair proportional financial marks with labeled amounts and supporting payments.
- **Do** preserve category matching scope, automatic save feedback, Retry, Discard, and Undo.
- **Do** preserve tabular amounts, focus visibility, reduced motion, and mobile navigation clearance.

### Don't:

- **Don't** combine currencies or insert decorative amounts into financial graphics.
- **Don't** treat bank email senders as payee identities.
- **Don't** drop failed or incomplete drafts or report success before a save response.
- **Don't** apply future category rules to earlier payments.
- **Don't** turn report composition into a universal layout rule or give persistent panels overlay shadows.
